When teaching step-by-step, give the instructions/structure for the current step first. Do NOT read or review the user's code mid-step, even if they jumped ahead and partially started writing it.

**Why:** The user finds it annoying when I review incomplete/in-progress code — they wanted the structure for the step laid out first so they could finish it on their own, THEN have it reviewed. Reviewing half-done work breaks their flow.

**How to apply:** When the user asks for step-by-step teaching:
1. Give the instructions for the current step (what to do, not how).
2. Wait for them to say "done" or similar.
3. ONLY THEN read their files and review.
Even if their IDE shows they've already started the next step, don't peek at it until they say they're ready. Relates to [[course-general-teaching-style]].
